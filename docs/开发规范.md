# 干饭签小程序 - 开发规范文档

> 本文档供 AI 开发助手（Codex / Cursor / Claude Code）阅读，定义项目所有开发规则。
> 开发前必读：所有代码必须严格遵守本文档规范。

---

## 一、项目概述

### 1.1 项目信息

| 项目 | 内容 |
|------|------|
| 项目名 | 干饭签（ganfanqian） |
| 项目类型 | 微信小程序原生开发 |
| 项目定位 | 一个可爱的"求签式"吃饭决策小工具 |
| 目标用户 | 每天纠结"吃什么"的打工人、学生 |
| 开发语言 | JavaScript + WXML + WXSS + JSON |
| 后端方案 | 第一阶段即使用微信云开发；本地存储仅用于必要缓存、临时 UI 状态和云端不可用时的降级说明 |
| 设计风格 | 手绘可爱卡通风、暖色系（米黄+红+绿） |

### 1.2 核心功能

1. **首页（抽签页）**
   - 用户选择午餐/晚餐
   - 点击"求一签"按钮随机抽取一道菜
   - 展示菜品图片和签文（吉祥话）
   - 可"再求一次"或"就吃这个"
   - 每日抽签次数限制（默认 3 次）

2. **我的页（管理页）**
   - 我的菜单：CRUD 食物列表（增删改查、启用禁用）
   - 已吃记录：今日 + 历史记录
   - 吃饭统计：本周顿数、最常吃食物、最常吃分类
   - 设置入口

### 2.4 设计原则

1. **可爱手绘风** —— 所有圆角必须够圆润，禁止使用直角
2. **温暖色调** —— 主色调为暖色，背景偏米黄/奶油色
3. **大量留白** —— 卡片之间间距充足，避免拥挤
4. **强调主体** —— 主操作按钮（求一签、就吃这个）使用立体阴影按钮
5. **避免使用** —— 渐变背景图、模糊滤镜、玻璃拟态等复杂效果

## 五、核心业务逻辑

### 5.1 抽签算法（必读）

**规则**：

1. 从 `foods` 中筛选 `enabled: true` 且 `mealType` 包含当前餐次的食物
2. 排除最近 N 天（默认 2 天）已吃过的（accepted: true 的记录）
3. 从剩余食物中**随机抽取一个**
4. 从签文库中随机抽取一句吉祥话
5. 抽签计数 +1，记录到云数据库 `daily_draws`
6. 创建云数据库抽签记录，但**不立即标记 accepted**
7. 用户点击"就吃这个"后才标记 `accepted: true`

**特殊情况**：

- 如果筛选后**没有可抽食物**（全被排除），降级策略：忽略"最近吃过"限制，从全部启用食物里抽
- 如果**仍然没有**（用户没添加食物或全禁用），返回提示："请先添加食物"
- 如果**今日抽签次数已达上限**，返回提示：可继续抽，但不再增加计数

### 5.2 统计逻辑

**本周统计**（周一到周日）：

```js
{
  totalMeals: 8,                   // 本周吃了几顿（accepted 的记录数）
  mostFrequentFood: {              // 最常吃的食物
    name: '猪脚饭',
    count: 3,
    image: '/assets/images/foods/food_zhujiaofan@2x.png'
  },
  mostFrequentCategory: {          // 最常吃的分类
    category: 'kuaican',
    label: '快餐',
    count: 5
  },
  topLunch: {                      // 午餐最多
    name: '黄焖鸡米饭',
    image: '/assets/images/foods/food_huangmenji_lg@2x.png'
  },
  topDinner: {                     // 晚餐最多
    name: '麻辣烫',
    image: '/assets/images/foods/food_malatang@2x.png'
  }
}
```

### 5.3 每日次数重置

**逻辑**：每次进入小程序，对比云数据库 `daily_draws` 中当前用户今天的记录：
- 如果没有今天的计数记录 → 初始化今天的计数为 0
- 如果已有今天的计数记录 → 继续使用当前计数
- `LAST_LAUNCH_DATE` 仅作为本地缓存辅助，不作为最终业务依据

代码位置：`app.js` 的 `onLaunch` 钩子。

### 5.4 云开发访问规则

- `app.js` 中必须初始化微信云开发。
- 云环境 ID、数据库集合名、权限规则需要在开发前确认；未确认时必须在任务说明中记录假设。
- 所有云数据库读写必须通过工具层封装，页面只调用业务方法。
- 云请求必须包含 `try/catch`，并返回可被页面展示的错误信息。
- 云数据为空时必须返回安全默认值，不能让页面直接崩溃。
- 云端不可用时可以读取本地缓存展示旧数据，但必须提示用户当前数据可能不是最新。

## 六、组件规范

### 6.1 组件设计原则

- **单一职责** —— 一个组件只做一件事
- **数据外注** —— 通过 `properties` 接收数据，不在内部查询本地存储或云数据库
- **事件外抛** —— 操作通过 `triggerEvent` 通知父组件
- **可复用** —— 避免硬编码业务文案

### 6.2 必做的组件清单

| 组件 | 用途 | properties | events |
|------|------|-----------|--------|
| `food-card` | 菜单列表的单个食物行 | `food`（Object）`mode`（'list' \| 'select'）| `tap` `toggle` `delete` |
| `food-toggle` | 开关 | `checked`（Boolean） | `change` |
| `result-card` | 抽签结果卡片（午餐签/晚餐签） | `food` `fortuneText` `mealType` | `accept` `redraw` |
| `stats-card` | 统计单项卡片 | `icon` `label` `value` `subtitle` | - |
| `empty-state` | 空状态 | `image` `title` `description` `actionText` | `action` |

### 6.3 组件示例：food-card

```js
// components/food-card/food-card.js
Component({
  properties: {
    food: { type: Object, value: {} },
    mode: { type: String, value: 'list' }  // list | select
  },
  methods: {
    onTap() {
      this.triggerEvent('tap', { food: this.data.food });
    },
    onToggle(e) {
      this.triggerEvent('toggle', {
        food: this.data.food,
        enabled: e.detail.value
      });
    }
  }
});
```

## 七、代码规范

### 7.1 JS 规范

```js
// ✅ 推荐
import { getFoods, saveFoods } from '../../utils/cloud-db';

const MAX_DAILY_DRAWS = 3;

Page({
  data: {
    foods: [],
    selectedMealType: 'lunch'
  },
  
  onLoad() {
    this.loadFoods();
  },
  
  // 加载当前用户的云端菜单数据。
  async loadFoods() {
    const foods = await getFoods();
    this.setData({ foods });
  }
});

// ❌ 避免
Page({
  data: {
    foods: wx.getStorageSync('foods') || []  // 不要在 data 里读存储
  },
  onLoad: function() {                       // 不用 function 关键字
    var that = this;                          // 不用 var，不用 that = this
    wx.getStorage({                           // 不用回调式 API
      key: 'foods',
      success: function(res) {
        that.setData({ foods: res.data });
      }
    });
  }
});
```

**规则**：

- 用 `const` / `let`，禁止 `var`
- 用 ES6 模块（`import` / `export`），禁止 `require`
- 优先用箭头函数，方法定义用简写
- 异步操作统一用 `async/await`，禁止回调地狱
- 字符串使用单引号 `'`
- 缩进 2 空格
- 主要函数必须写注释，说明用途、关键参数或重要边界
- 云开发调用、抽签算法、统计逻辑必须写解释性注释
- 避免无意义逐行注释，不要给显而易见的赋值写废话注释

### 7.2 WXML 规范

```html
<!-- ✅ 推荐 -->
<view class="container">
  <view class="header">
    <text class="title">{{title}}</text>
  </view>
  <view 
    wx:for="{{foods}}" 
    wx:key="id"
    class="food-item"
    bindtap="onFoodTap"
    data-id="{{item.id}}"
  >
    <image class="food-img" src="{{item.image}}" mode="aspectFit" />
    <text class="food-name">{{item.name}}</text>
  </view>
</view>

<!-- ❌ 避免 -->
<view style="padding: 20rpx; background: #fff;">  <!-- 避免 inline style -->
  <view wx:for="{{foods}}">                       <!-- 缺少 wx:key -->
    <image src="{{item.image}}"></image>
  </view>
</view>
```

**规则**：

- 禁止 inline style（除非动态计算的位置/旋转角度）
- `wx:for` 必须配 `wx:key`
- 图片必须指定 `mode`（推荐 `aspectFit` 或 `widthFix`）
- class 命名 BEM 风格：`.block__element--modifier`

### 7.3 WXSS 规范

```css
/* ✅ 推荐 */
.food-card {
  display: flex;
  align-items: center;
  padding: var(--spacing-md);
  background: var(--color-bg-card);
  border-radius: var(--radius-md);
  box-shadow: var(--shadow-sm);
}

.food-card__image {
  width: 96rpx;
  height: 96rpx;
}

.food-card__name {
  font-size: var(--font-size-lg);
  color: var(--color-text-primary);
}

/* ❌ 避免 */
.food-card {
  padding: 24rpx;                /* 应该用变量 */
  background: #ffffff;           /* 应该用变量 */
  border-radius: 24px;           /* 应该用 rpx */
}
```

**规则**：

- 所有颜色用变量
- 所有间距尽量用变量
- 单位统一用 `rpx`，禁止 `px`（边框 1px 除外）
- 避免 `!important`
- 避免过深嵌套（最多 3 层）

- 把大量页面放分包（`packageSub/`）
- 图片放 `assets/`，必须经 TinyPNG 压缩

### 8.2 图片优化

```html
<image 
  src="/assets/images/foods/food_zhujiaofan@2x.png" 
  mode="aspectFit"
  lazy-load="{{true}}"
/>

<!-- ❌ 避免 -->
<image src="https://external.com/img.png" />  <!-- 不要用外链，除非云存储 -->
```

### 8.3 setData 优化

```js
// ✅ 推荐：只更新变化的字段
this.setData({
  'foods[2].enabled': true
});

// ❌ 避免：全量 setData
this.setData({ foods: this.data.foods });  // 触发整个数组 diff
```

### 8.4 长列表

- 大于 50 项的列表用 `<scroll-view>` 或虚拟列表
- 使用 `wx:key` 提升 diff 性能
- 图片用 `lazy-load`

## 十三、常见禁止事项

❌ **绝对禁止**：

1. 使用 `eval()`、`new Function()`
2. 使用 inline style（动态计算除外）
3. 使用 `var`
4. 在 `data` 中直接调用 `wx.getStorageSync`
5. 硬编码颜色值（必须用 CSS 变量）
6. 硬编码业务文案在组件内部
7. 网络请求或云开发调用未做错误处理
8. 用户数据未做空值判断
9. 图片不指定 `mode`
10. 列表渲染无 `wx:key`
11. 页面或组件中散落直接调用云数据库

⚠️ **避免使用**：

1. 复杂的渐变背景
2. 模糊滤镜（性能差）
3. 大量动画同时执行
4. `setData` 频繁调用（合并提交）
5. 嵌套层级超过 3 层的组件
6. 超长的页面 JS 文件（超过 500 行考虑拆分）
